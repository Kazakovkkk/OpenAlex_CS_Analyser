# Бенчмарки MVP (Спринт 5, §6.16–6.17)

Замеры сделаны на локальной машине, `CGO_ENABLED=0`, ClickHouse-запись отключена
(`NoopSink`), если не указано иное. Все числа — из строки `ingest: result`.

## Что уже измерено

### Проекция и объём чтения

Файл `updated_date=2026-08-13/part_0071.parquet`, 50,46 MiB, режим Range + prefetch:

| Ревизия схемы | Прочитано | Доля файла | HTTP-запросов |
|---|---|---|---|
| 34 колонки (до MVP) | 15,22 MiB | 30,2 % | 25 |
| без `abstract` | 8,42 MiB | 16,7 % | 15 |
| MVP: 12 leaf-колонок | **2,71 MiB** | **5,4 %** | 15 |

Нижняя граница (только нужные колонки, идеальный план) — 2,34 MiB / 4,6 %.

## Сравнение режимов чтения на одном файле

Файл `updated_date=2026-08-13/part_0071.parquet`, 50,5 MiB, команда `etl bench --file …`:

| Режим | Прочитано | Доля файла | HTTP-запросов | Время |
|---|---|---|---|---|
| Full GET (базовая линия) | 50,46 MiB | 100 % | 1 | 12,06 с |
| **Range + prefetch** | **2,71 MiB** | **5,4 %** | 15 | **3,60 с** |

Экономия трафика — **18,6 раза**, время чтения — в 3,4 раза меньше. Колонок в
проекции 12, план из футера — 2,34 MiB, фактически прочитано 2,71 MiB (перебор
0,37 MiB на границы страниц).

## Что ещё не измерено


**Базовая линия «один Full GET на файл» на том же 50 MiB файле.** В этом сеансе
сравнить не удалось: выборка `--max-files` берёт первые файлы раздела, а они
мелкие (< 16 MiB), поэтому оба режима идут через Full GET и дают одинаковые
334 004 байта на пяти файлах.

Чтобы снять сравнение, нужен запуск на конкретном крупном файле:

```bash
# базовая линия: Full GET, без Range и плана из футера
etl ingest --source s3 --from-date 2026-08-13 --full-get-threshold-mb 1000000

# оптимизированный режим
etl ingest --source s3 --from-date 2026-08-13
```

и сравнение `bytes_read` / `http_requests` / `elapsed` из строки результата.

**Пик RSS** по режимам — не снимался. Методика: `GODEBUG=gctrace=1` либо
`runtime.MemStats` в конце прогона на 10k записей.

**`benchstat` по трём прогонам** — не запускался.

## Оговорки

- `--full-get-threshold-mb` — это существующий порог библиотеки; отдельного
  флага «выключить prefetch» пока нет. Для честной базовой линии его значение
  выставляется заведомо большим, чтобы каждый файл читался целиком.
- `docs/` сейчас в `.gitignore`, поэтому этот файл в репозиторий не попадёт,
  пока правило не исправлено (это часть Спринта 6).
